# ADR-0003 — Memory Lifecycle Primitives

> Bitemporal validity & soft-delete for revisable memory. Reproduced here for
> site-internal navigation; the authoritative copy lives at
> [docs/decisions/adr-0003-memory-lifecycle.md](https://github.com/m-koerbaecher/memsidecar/blob/main/docs/decisions/adr-0003-memory-lifecycle.md)
> in the repo.

**Status:** Proposed · **Extends:** [ADR-0001](./adr-0001.md) · **Decision
drivers:** revisability as a first-class substrate concern; the agent owns
judgment, the sidecar owns storage

## 1. Context

The `semantic` block was originally *destructive*: `Upsert` was a
last-writer-wins overwrite with no history, and `Delete` physically removed a
row. There was no way to express that a fact *was* true and later stopped
being true, nor to retract a fact while keeping it auditable.

The agent-memory study (arXiv:2606.24775) identifies the absence of this
lifecycle governance as its single most damaging gap: without it a memory
system keeps returning superseded facts — the paper's **"hallucinations of
the past" (Finding 3)**. The systems that handle knowledge updates best bind a
later fact to what it revises and *logically invalidate* the old one via
validity timestamps rather than deleting it. The same study shows (Finding 5)
that this maintenance must stay **localized** — a bounded, id- or
filter-targeted operation, never a global rewrite.

memsidecar is the natural owner of these primitives: it sits on the read/write
path, scopes by namespace and capability, and already carries a `created_at`.
What it lacked were the *columns* and the *default read filter* that make
revisability expressible.

## 2. Decision

Add **bitemporal validity** and **soft-delete** to the `semantic` record, with
a default "as-of now" read filter, and give `Delete` an explicit hard-delete
escape hatch.

Three new optional fields on the record:

| Field | Meaning | Default on write |
|---|---|---|
| `valid_from` | wall-clock time the fact becomes true (valid time) | `now()` if unset |
| `valid_to` | exclusive upper bound — the fact stops being true here | unset = open-ended (still valid) |
| `deleted_at` | soft-delete tombstone; row is retracted but retained | unset = live |

Read semantics (`Search`):

- **Default** (as-of *now*): a record is returned only when
  `deleted_at IS NULL AND valid_from <= now() AND (valid_to IS NULL OR valid_to > now())`.
  Invalidated, retracted, and not-yet-valid records are invisible — this
  closes Finding 3 for every existing caller **without any client change**.
- **`as_of <t>`**: evaluate the same predicate at time `t` — point-in-time
  recall ("what did we believe on date X").
- **`include_invalidated`**: bypass the lifecycle predicate and return
  tombstoned / expired / future rows too — for audit and supersession-chain
  inspection.

Write semantics:

- `Upsert` sets `valid_from`, `valid_to`, `deleted_at` from provided-or-default
  values. Because `deleted_at` defaults to null, **re-upserting an id
  resurrects it** unless the caller explicitly retracts.
- `Delete` gains a `hard` flag. **Soft (default):** set `deleted_at = now()`
  on a live row; it stays reachable via `include_invalidated`. **Hard:**
  physical `DELETE`, as before.

Existing rows and callers are unaffected: the new columns default to a live
state, so every current row reads as valid and every current `Search`/`Delete`
call behaves as before.

## 3. Scope

**Is:** inert storage columns plus a default read filter, both owned by the
substrate. The agent supplies `valid_from`/`valid_to` and decides when to
retract; the sidecar stores the values and applies a `WHERE` clause. No LLM is
invoked; no engine is reimplemented.

**Is not:** automatic supersession/conflict inference, consolidation or
summarization, or global reorganization. Every operation is id-targeted or
filter-scoped with a required bound — localized per Finding 5.

## 4. Delivery

Delivered as four tickets behind the `semantictest` conformance suite,
exercised by both the in-memory and pgvector harnesses:

| Ticket | Scope |
|---|---|
| **U1** | Bitemporal validity + soft-delete columns and the default as-of-now read filter (this ADR). |
| **U2** | `supersedes`/`source` provenance pointers — bind a later fact to the ids it revises in one localized transaction. |
| **U3** | Bulk `Expire` by filter, with a required `max_rows` bound. |
| **U4** | Semantic optimistic-concurrency (`version`/`if_version` CAS) at parity with `kv`. |

All four are implemented in the walking skeleton. See the
[Semantic block reference](../blocks/semantic.md) for the client-facing API.
