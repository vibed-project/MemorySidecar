# ADR-0001 — Memory Sidecar for Agentic Systems

> The original Architecture Decision Record that this project is built
> from. Reproduced here for site-internal navigation; the authoritative
> docx + markdown copies live at
> [docs/decisions/](https://github.com/m-koerbaecher/memsidecar/tree/main/docs/decisions)
> in the repo.

**Status:** Proposed · **Decision drivers:** Self-hosted OSS; bring-your-own
backends; framework-agnostic protocol

## 1. Context

Agentic systems — single agents, multi-agent crews, long-running
autonomous workflows — all need persistence. In practice this means a
stack of disparate stores: a KV cache for tool results, a vector database
for semantic recall, an append-only log for episodic history, blob
storage for generated artifacts, and some form of working memory that
outlives a single inference call. Every popular framework (LangGraph,
CrewAI, Autogen, Mastra, bespoke stacks) re-implements this plumbing in
incompatible ways.

The result: agent code is tightly coupled to specific backends,
multi-agent memory sharing is ad-hoc, access control is either absent or
framework-specific, and swapping Pinecone for Qdrant — or Redis for
Postgres — means rewriting agent code.

## 2. Decision

Build a self-hosted, OSS, framework-agnostic **Memory Sidecar**
implementing five building blocks (`kv`, `episodic`, `semantic`,
`artifact`, `lease`) over pluggable backends, with capability-based auth
and a policy engine. Ship a v0.1 reference distribution with Postgres +
pgvector + S3-compatible blob store as the default substrate.

## 3. Building blocks

| Block | Purpose | Typical backends |
|---|---|---|
| **kv** | Typed, TTL'd key-value for tool-result caching and scratchpads | Redis, Postgres, in-memory |
| **episodic** | Append-only log of agent events, messages, tool calls | Postgres, SQLite, Kafka |
| **semantic** | Embed-and-search over arbitrary records | pgvector, Qdrant, Pinecone, Weaviate |
| **artifact** | Blob storage with metadata for generated files | S3, MinIO, local FS |
| **lease** | Distributed locks and leases for shared-state coordination | Redis, etcd, Postgres advisory locks |

## 4. Cross-cutting concerns

- **Identity & capability** — every request carries a signed token scoped
  to `(tenant, agent, namespace_pattern, ops, ttl)`.
- **Policy engine** — declarative rules for retention, PII redaction,
  encryption, rate limiting, tenant isolation.
- **Observability** — OpenTelemetry traces, Prometheus metrics,
  structured audit log.
- **Backend abstraction** — driver interface per building block;
  backends configured in YAML.

## 5. Alternatives considered

| Option | Why rejected as primary |
|---|---|
| Library, not sidecar | Forces every agent runtime to embed it. Loses central policy enforcement and per-deploy backend swap. |
| Use Dapr directly | No semantic-search primitive, no agent-shaped episodic log, no embedder abstraction. |
| Adopt Letta / mem0 / Zep as-is | Bake in opinionated memory models, are framework-coupled or SaaS-leaning. |
| Build on top of one vector DB's API | Locks users into that vendor. |

## 6. Roadmap

| Milestone | Scope |
|---|---|
| **v0.1 (MVP)** | kv + episodic + semantic; pgvector + Postgres backends; capability tokens; YAML policy; Python SDK; OTel traces. |
| **v0.2** | artifact + lease blocks; S3 driver; Qdrant driver; TypeScript SDK; admin CLI; hot-reload config. |
| **v0.3** | Multi-tenant hardening; Rego policy support; second embedder providers; reference Helm chart; Grafana dashboards. |
| **v0.4** | Streaming primitives (Kafka episodic); CRDT-backed shared working memory experiment; framework integrations (LangGraph, CrewAI adapters). |

## 7. Where the walking skeleton lands

The current implementation covers everything in v0.1 plus most of v0.2:
HTTP gateway, artifact + lease blocks, S3 driver, Python SDK, real
embedders (Ollama + OpenAI), real policy DSL, OTLP exporter +
Prometheus, mTLS, key rotation, hot reload, Helm chart, container
image. See the [overview](/) for the current status banner.
